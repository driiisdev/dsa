1. Algorithm
An algorithm is a set of well-defined instructions to solve a particular problem.

- Characteristics
. well defined inputs and outputs
. each step should be clear and unambiguous
. Language independent

- why algorithms
. as a developer, one is going to come across problems that needs to be solved
. learning algorithm translates to learning different techniques to efficiently solve those problems
. one problem can be solved in many ways using different algorithms
. every algorithm comes with its own tradeoffs when it comes to performance

2. Measuring Performance
The absolute running time of an algorithm cannot be predicted, since it depends on a number of factors
- programming language used to implement the algorithm
- the computer the program runs on
- other programs running at the same time
- quality of the operating system

NB:- the performance of an algorithm is evaluated "in terms of its input size"

3. Time and Space Complexity
- Time complexity:- amount of time taken by an algorithm to run, as a function of input size
- Space complexity:- amount of memory taken by an algorithm to run, as a function of input size

by evaluating against the input size, the analysis is not only machine independent but the comparison is also more appropriate

there is no one solution that works every single time. it is always good to know multiple ways to solve the problem and use the best solution, given your constraints

if your app needs to be very quick and has plenty of memory to work with, you don't have to worry about space complexity

if you have very little memory to work with, you should pick a solution that is relatively slower but needs less space

- How to represent complexity?
. Asymptotic notations
  - mathematical tools to represent time and space complexity
  (1) Big-O Notation - Worst case complexity *
  (2) Omega Notation - Best case complexity
  (3) Theta Notation - Average case complexity

4. Big-O Notation
The worst case complexity of an algorithm is represented using the Big-O notation
Big-O notation describes the complexity of an algorithm using algebraic terms

It has two important characteristics:-
  . It is expressed in terms of the input
  . It focuses on the bigger picture without getting caught up in the minute details

example 1: an algorithm implement in a program function (loop version):
`
  (js)
  function summation(n) {
    let sum = 0;
    for(let i = 1; i <= n; i++){
      sum += i
    }
    return sum;
  }

  [analysis]
  step 1: count the number of times a statement executes based on the input size
    "let sum = 0" runs once -> 1
    "for loop" runs as a function of its condition 'n' (e.g if 'n' = 3) runs thrice -> 3
    "return sum" runs once -> 1

    :. 3 + 2 = n + 2 (since n is 3, and the reason why the loop runs thrice)

  step 2: focus on the bigger picture without getting caught up in the minute details
    "n + 2" - n here is bigger picture here, if n is 100, it'll be  "100 + 2", hence 'n' is the bigger picture here

  step 3: final review - time complexity can be said to "Big-O of (n)" same as "O(n)"

 mathematically: O(n) - Linear
 the time complexity of the algorithm implemented in the function above can be said to be "O(n) - Linear", as the input doubles, time roughly doubles.
`

example 2: an algorithm implement in a program function (formula version):
`
function summation(n){
  return((n*(n+1))/2);
}
[analysis]
  step 1: count the number of times a statement executes based on the input size
    "return((n*(n+1))/2);" runs once -> 1

  step 2: focus on the bigger picture without getting caught up in the minute details
    regardless of how large 'n' gets, only one statement get executes. the input size has no effect on the number of steps

  step 3: final review - time complexity can be said to "Big-O of (1)" same as "O(1)"
 mathematically: O(1) - Constant
 the time complexity of the algorithm implemented in the function above can be said to be "O(1) - Constant", No matter the input size, time stays the same.
`

example of two nested  loop function:
`
for (i = 1; i <= n; i++) {
  for (j = 1; j <= i; j++) {
    //statement of the code to be executed
  }
}
`
[analysis]
time complexity : the loop is nested just twice, hence input gets ??run or loop?? twice "n^2"
function/program with such algorithm is said to be quadratic - O(n^2) with formula ~ 3n^2 + 5n + 1. the less dominant in the formula is "5n + 1"

example of three nested  loop function:
`
for (i = 1; i <= n; i++) {
  for (j = 1; j <= i; j++) {
    for (k = 1; k <= j; k++) {
      //statement of the code to be executed
    }
  }
}
`
[analysis]
time complexity : the loop is nested just thrice, hence input gets ??run or loop?? thrice "n^3"
function/program with such algorithm is said to be cubic - O(n^3) with formula ~ n^3 + 3n^2 + 5n + 1. the less dominant in the formula is "3n^2 + 5n + 1"

example: logarithmic algorithm implemented in a function (loop version)
`
function logExample(n){
  let i = 1;

  while(i <= n){
    i = i * 2;
  }
}
`
[analysis]
step 1: count the number of times a statement executes based on the input size

The key statement is:

i = i * 2;

Let’s track how i grows:

1st run → i = 2
2nd run → i = 4
3rd run → i = 8
4th run → i = 16
...

So after k runs:

i = 2^k

Loop stops when:

2^k >= n

step 2: focus on the bigger picture without getting caught up in the minute details

We solve:

2^k >= n

Take log on both sides:

k ≈ log₂(n)

So the loop runs about log(n) times.

As n grows, the number of steps increases very slowly because we keep doubling.

step 3: final review

Time complexity can be said to:

O(log n)

mathematically: O(log n) – Logarithmic

The time complexity of the algorithm implemented in the function above can be said to be "O(log n) - Logarithmic", because the input size is reduced (or grows) exponentially each step, so the number of operations increases slowly as n increases.

space complexity:
O(1) - Constant
-> if the algorithm doesnot need extra memory, or the memory needed doesnot depends on the input size, space complexity is said to be Constant.
O(n) - Linear
-> if the extra space need by the algorithm grows as the input size grows, the space complexity is said to be Linear.
O(logn) - Logarithmic
-> if the extra space need by the algorithm grows or reduces as the input size grows or reduces exponentially, the space complexity is said to be logarithmic.

nb: quadratic/ cubic space complexity should be avoided when possible.

Ponits to note
multiple algorithms exist  for the same problem and there is no one right solution. different algorithms work well under different constraints.

the same algorithm with the same programming language can be implemented in different ways

when writing programs at work, dont lose sight of the bigger picture. rather than writing clever code, wriete code that is simple to read and maintain.
